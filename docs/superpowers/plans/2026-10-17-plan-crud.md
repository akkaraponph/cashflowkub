# Monthly Plan CRUD (`/plan?tab=monthly`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user add, edit and delete plan items (income, expense, savings) for any month on the Monthly tab of `/plan`.

**Architecture:** The REST CRUD (`POST /api/v1/plan`, `PATCH|PUT|DELETE /api/v1/plan/[id]`) and Zod validation already exist in `src/server/plan/service.ts`; the page is read-only and hard-wired to `CURRENT_MONTH`. So the work is: make the page month-aware (`?month=YYYY-MM`), add a client dialog following the existing `GoalDialog` pattern (pure form model in its own file, dialog calls `apiFetch`, then `router.refresh()`), and close two small server gaps (stable ordering of new items, shared month regex).

**Tech Stack:** Next.js 16 App Router, React 19, Prisma 7, Zod 4, Tailwind 4 + shadcn/radix, sonner, Vitest (`unit`, `api`, `e2e` projects).

**Spec:** The user's request in chat (2026-10-17): "http://localhost:3000/plan?tab=monthly it should have CRUD for management plan". Domain reference: `docs/knowledge/spreadsheet-planner.md` §5 (the planner's plan log: month + item + planned amount, three lists income / expenses / savings).

## Calls I made (check these)

- **Scope is the Monthly tab only.** Summary and Assets tabs stay read-only, but the Summary tab follows the selected month because it reads the same `getPlan(month)`.
- **`actual` is editable** in the dialog. Nothing else populates it today (it is not derived from transactions), so without this the "จริง/Actual" column could never change. Deriving it from transactions is a separate feature.
- **One name for both languages**, same as goals: new items store `name` and `th` = the typed name; editing leaves an unchanged name out of the PATCH so the other language's seeded name survives.
- **Amounts stay integer baht** (schema is `Int`). Like the goal form, a typed `12.5` rounds to `13`.
- **Not building:** "copy last month's plan", suggested amounts (planner §5), due dates, drag-reorder. YAGNI until asked.
- **`AGENTS.md` mentions `docs/knowledgebase/` and `docs/postman-collections/`; neither exists** (only `docs/knowledge/`). No endpoint is added or changed, so no Postman/OpenAPI work; the knowledge note goes in `docs/knowledge/spreadsheet-planner.md`.

## Global Constraints

- JSON fields `snake_case`-style rule from `AGENTS.md`: PlanItem fields (`type`, `name`, `th`, `planned`, `actual`, `month`, `sort`) already comply; add no new fields.
- Month format `YYYY-MM`, regex `/^\d{4}-(0[1-9]|1[0-2])$/`. Invalid `?month=` on the page falls back to `CURRENT_MONTH`; invalid month on the API stays a 400.
- Plan `type` is exactly `income | expense | savings`.
- All user-facing strings go through `src/lib/i18n.ts`, added to both `en` and `th`.
- No new runtime dependencies.
- Run tests with `npm test` (unit + api) from `cashflowkub/`; typecheck `npm run typecheck`; lint `npm run lint`.
- Commit after every task, ending the message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- `/plan?tab=monthly&month=garbage` (or `2026-13`) renders the current month, not a 400/500 page.
- A month with no plan items (e.g. `2025-01`) renders three empty sections with an add button each, zero totals and no `NaN%` anywhere.
- Amount text a person really types — `฿1,200`, `1 200`, blank, `-5`, `abc` — blank = 0, comma/baht/space stripped, negative or unreadable disables Save.
- Name of only spaces is rejected; editing a seeded item while the UI is Thai does not overwrite its other-language name.
- Deleting twice / editing an item someone else just deleted gives a 404 toast, and two items created in a row keep creation order (same `sort`).

### Task 2: Pure form model for the plan-item dialog

**Files:**
- Create: `cashflowkub/src/lib/money-input.ts` (extract from `goal-form.ts`)
- Modify: `cashflowkub/src/app/(app)/goals/goal-form.ts` (import `parseMoney` instead of the private `money`)
- Create: `cashflowkub/src/app/(app)/plan/plan-form.ts`
- Test: `cashflowkub/tests/unit/plan-form.test.ts`

**Interfaces:**
- Produces (`money-input.ts`): `export function parseMoney(raw: string, blank: number): number` — strips `,` `฿` whitespace; blank → `blank`; unreadable → `NaN`; otherwise `Math.round(Number(s))`.
- Produces (`plan-form.ts`):
  - `export type PlanType = 'income' | 'expense' | 'savings'`
  - `export interface PlanItemForm { name: string; planned: string; actual: string }`
  - `export const emptyPlanForm: PlanItemForm` — `{ name: '', planned: '', actual: '' }`
  - `export function formFromPlanItem(i: { name: string; th: string; planned: number; actual: number }, lang: Lang): PlanItemForm` — name via `localized(lang, i.name, i.th)`, numbers as `String`.
  - `export function planItemBody(f: PlanItemForm, ctx: { type: PlanType; month: string }, original?: PlanItemForm): Record<string, unknown> | null`
    - `null` when trimmed name is empty, or planned/actual (blank = 0) is `NaN` or negative.
    - Create (no `original`): `{ type, month, name, th: name, planned, actual }`.
    - Edit (`original` given): `{ planned, actual }` plus `{ name, th: name }` only when the trimmed name differs from `original.name.trim()`; never sends `type`/`month`.
- Consumes: `localized`, `Lang` from `@/lib/i18n`.

  - blank/space name → `null`; `planned: '-1'`, `actual: 'abc'` → `null`.
  - `planItemBody({ name: ' Rent ', planned: '฿12,000', actual: '' }, { type: 'expense', month: '2026-06' })` toEqual `{ type: 'expense', month: '2026-06', name: 'Rent', th: 'Rent', planned: 12000, actual: 0 }`.

  - `formFromPlanItem({ name: 'Rent', th: 'ค่าเช่า', planned: 12000, actual: 11000 }, 'th')` toEqual `{ name: 'ค่าเช่า', planned: '12000', actual: '11000' }`; with `'en'` name is `'Rent'`.
  - edit with unchanged name: body has no `name`/`th`/`type`/`month`; changed name: includes `name` and `th`.
  - Run `npm run test:unit -- goal-form` must still pass after the extraction.
